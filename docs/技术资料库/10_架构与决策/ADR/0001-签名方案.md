# ADR-0001 签名方案：改用新正式 keystore，卸载重装后回灌数据

- **编号**：0001
- **日期**：2026-11-20
- **状态**：已确认（演练通过 2026-11-20，真机执行待批准）

## 问题背景

手机已装 `com.zhuli.app` v0.16-full / versionCode 16，其实测签名证书 SHA-1 为 `c6:f8:70:49:7d:7e:06:89:37:3e:ae:b0:1c:0b:3e:1e:48:5f:2a:e9`，该证书来自**旧电脑**的 `~/.android/debug.keystore`（DN 为 `CN=Android Debug`）。本机 debug 证书为 `1d:8d:61:0d…`，两者不同，因此：

- 本机构建的 APK 无法覆盖安装（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`）；
- 换签名必须走卸载，而卸载会删除 `/data/data/com.zhuli.app` 全部数据；
- 计划缺陷 D7 指出：现有加密备份用 Android Keystore 密钥加密，**跨设备/重装后不可解**，不能作为回灌通道。

## 当前方案（候选 a）

找回旧机 `~/.android/debug.keystore`，本机继续用 debug 签名构建，直接覆盖安装，零数据风险。

## 候选方案（b，最终选择）

新建正式 keystore（RSA 4096，有效期 10000 天），**签名到 debug 构建**（保留 `debuggable=true`），走「卸载 → 安装新签名 APK → 用 T-A1 明文库回灌」链路。

## 比较依据

| 维度 | a 旧 debug keystore | b 新正式 keystore |
|---|---|---|
| 数据风险 | 无 | 卸载即丢，依赖 T-A1 备份回灌 |
| 前提 | 旧机可访问 | 只需本机 |
| 长期性 | debug 证书 30 年有效，但只是调试证书 | 正式证书，语义正确，可长期升级 |
| 回灌能力 | 不需要 | 需要 `run-as`（要求 debuggable） |
| 可验证性 | 无法验证（旧机不可达） | 可演练（模拟器） |

**事实核查结果**：旧机已不可访问（用户 2026-11-20 确认），方案 a 的前提不成立，故选 b。

## 最终选择

b。理由：a 的物理前提消失；b 虽然引入一次不可逆卸载，但 T-A1 已取得完整明文库（360,448 字节，`integrity_check=ok`，`user_version=11`，7 表行数在案），且回灌链路可先在模拟器完整演练。

## 影响模块

`app/build.gradle.kts`（signingConfig）、`local.properties`（口令与路径，不入库）、发布流程（每次装机必须是同一 keystore）、`BLOCKERS.md`（keystore 备份责任）。

## 风险

1. **keystore 丢失 = 以后每次升级都要卸载回灌**。必须与数据库备份分开、双份保存。
2. 回灌链依赖 `run-as`。若将来改成 release 构建（`debuggable=false`），回灌通道立即失效，届时必须依赖 T-E2 的可迁移加密备份。
3. 卸载到回灌之间手机端处于「无数据」状态，期间到达的通知不会被采集。
4. 口令存在 `C:\Users\a\.zhuli\keystore.pass`，该文件泄露等同 keystore 泄露。

## 验证方式

1. 模拟器演练：装旧签名包 → 造数据 → 用新签名包覆盖（预期失败）→ 卸载 → 装新签名包 → `run-as` 回灌 T-A1 库 → 校验 7 表行数与 `user_version=11`。
2. 真机执行后同样校验，并把结果记入 CURRENT_STATE。

**代价（必须记入文档）**：
1. 云端 API Key 无法恢复——`zhuli_secure.xml` 由 Android Keystore 别名加密，卸载即销毁密钥，密文成废纸，必须重新填 Key；
2. `zhuli_prefs.xml` 按用户决定未备份，云端地址、模型名、人格、隐私模式、免打扰时段等需重配；
3. 无障碍服务与厂商「自启动/后台运行」开关需手动重开。

## 回滚方案

- 演练阶段：模拟器可整机删除，无成本。
- 真机阶段：若回灌失败，手机端数据已丢，但 PC 侧 `zhuli_inbox_2026-11-20.db` 仍可重试；若新包无法启动，可回退到旧签名 APK，但**旧签名已无法安装**（旧 keystore 不存在），因此真机执行前必须确认新包能正常启动（先在模拟器验过）。
