# zhuli 开源项目复用评估报告 V1.0

日期：2026-11-20
性质：V2.0 执行计划第五部分"开发依据库 / 开源项目候选清单"的落地成果；三路并行网络调研（数据与工程层 / 端侧 AI 层 / Agent·记忆·UI·自动化层）汇总。
口径：按 V2.0 原则核查——License（个人自用，AGPL/GPL 可接受）、活跃度、Android 16 + arm64 + **16KB 页**兼容、本地优先、不为用开源而引依赖。
复用四档：**直接依赖**（加 AAR/Maven/源码模块）/ **移植规则**（抄规则、prompt、算法到自研代码）/ **仅设计参考** / **不建议**。
⚠ 标记 = 调研中未能完全核实、采用前必须验证的项。所有 URL 来自本次搜索结果。

---

## 0. 结论速览

1. **端侧 AI 两条依赖链全包，且都无 16KB 障碍**：
   - `sherpa-onnx` 一个 AAR = ASR（SenseVoice）+ VAD（silero 内置）+ 将来 TTS；
   - `LiteRT-LM` 一个 Maven 依赖 = Embedding（EmbeddingGemma）+ 本地 LLM（Qwen3-0.6B）。
   - **ModelStore 已下载的三个模型全部直接对口**，总集成量约 7–10 人日——这是阶段 H 最大的工期节省。
2. **阶段 C 检索修复有现成路线**：jieba-analysis 分词 + 普通 FTS5 表（绕开外部内容表恒空缺陷与 trigram 依赖）+ RRF 混合排序（约 20 行 Kotlin）。
3. **阶段 E 加密有官方正路**：`sqlcipher-android` 4.6.1+ 官方支持 16KB（旧 android-database-sqlcipher 已 EOL，禁用），`sqlcipher_export()` 提供明文→加密迁移原语。
4. **聊天壳二开路线被证实可行**：RikkaHub 已迁 org（rikkahub/rikkahub），Kotlin/Compose/多模块、自带 MCP 工具与 Room 记忆层，注入自研 core 现实可行，省 3–4 周 UI。
5. **Agent 不引框架**：6 工具 × 3 轮循环引 koog/langchain4j 属依赖膨胀；自研保留，借鉴设计 + 补一个轻量 JSON Schema 校验。
6. **记忆系统无端侧现成库**：mem0/letta/memobase/graphiti 全是服务端，但它们的抽取 prompt、冲突决策、分层结构、时效字段值得移植到 SQLite 记忆层——省的是设计时间不是代码时间。
7. **保活灰产库一律不用**（1px/双进程/无声音乐在 Android 16 已失效或违规）；dontkillmyapp.com **无 Nubia 专页**，厂商引导页要靠社区经验 + 自研实测。

| 候选 | License | 结论 | 说明 |

关键证据与备选：
- sherpa-onnx 中文实测 CER 8.17 vs whisper small 22.12，CPU 约 20× 实时；int8 模型 RAM 峰值约 600–770MB（issue #4056，16GB 无压力）；另有 QNN Android demo。
- **vosk 排除**（16KB issue #1752 未解决、2024-04 后停更）；whisper.cpp tiny/base 中文 CER 约 38%/29% 不作中文主力；MLC-LLM 团队重心转 WebLLM、模型需预编译，不作首选（与选型报告历史决策一致）。
- LiteRT-LM 速度参考：Gemma3-1B S24U GPU 解码 52.5 t/s；8 Elite 系 NPU 1B 级 100+ t/s；Qwen3-0.6B QNN HTP 实测 32.6 t/s（SM8850 MNN 数据，8 Elite 待自测）。
- llama.cpp（MIT，官方 Android 示例 docs/android.md）作备选 + bge GGUF embedding 共用运行时；NDK r28+ 或 max-page-size=16384 自编即 16KB 合规。
- Qualcomm 直集成（QNN/QAIRT）门槛高、context binary 与 SoC 绑定；**优先 LiteRT-LM 间接吃 NPU**，AI Hub 预编译 bundle（如 GenieX Qwen3-0.6B）作对照。
- ONNX Runtime Mobile 官方预编译 16KB 未决——**这是不选 ORT 路线的决定性理由**（sherpa 自带构建已修）。

**净结论**：两条依赖链（sherpa-onnx AAR + LiteRT-LM Maven）覆盖 ASR/VAD/TTS/Embedding/LLM 五域，三个已下载模型零浪费，总计约 7–10 人日。对比自研/ORT/MLC 路线节省数周。
