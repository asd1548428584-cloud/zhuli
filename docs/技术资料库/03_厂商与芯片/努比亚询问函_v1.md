致努比亚 / 中兴开发者支持团队：

您好。我方在努比亚 Z70 Ultra（NX733J，Nebula AIOS 2.0.14MR2，Android 16 / API 36）上开发一款**个人自用的助理类应用**（包名 `com.zhuli.app`，不上架应用商店，仅本人设备使用），希望咨询以下能力是否对普通第三方应用开放，有无公开 SDK、文档或权限申请流程：

**1. 系统 AI 能力**
`AIService`（`com.zte.ai.IAIManager`）与 `vendor.zte.aimodel` 下的 BERT / BGE / LLM / Voice 模型，是否提供面向第三方应用的调用接口？若有，是否需要在开发者平台申请签名级权限？

**2. 自动化编排与系统助手**
`com.zte.orchestrationtools`（自动化编排）与 `com.zte.aiassistant`（系统 AI 助手）是否开放意图/技能接入？例如第三方应用能否注册可被系统助手调用的能力。

**3. 健康数据**
`nubia.system_healthy` / `cn.nubia.healthy` 的健康数据（步数、心率、睡眠）是否会写入 Android 标准 **Health Connect**？第三方应用通过 Health Connect 读取时，数据是否完整？若不走 Health Connect，是否有其他第三方可用的读取方式？

**4. 后台运行与自启动**
`superkiller` / `cfreezer` / `AutoLaunch` / `DefendManagerService` 这套后台管控机制，第三方应用应如何申请稳定的后台运行与开机自启动白名单？是否有官方文档说明判定标准（例如加入电池优化白名单是否足够）？
另外，`AlarmManager.setAlarmClock` 在息屏长周期下的调度策略是否有公开说明？实测本机 `setExactAndAllowWhileIdle` 会被限流，`setAlarmClock` 正常，希望确认这是设计行为还是可配置项。

**5. 版本适配说明**
星云 OS 后续版本（2.0.14MR2 之后）对第三方应用的后台、闹钟、通知监听、无障碍服务是否有行为变更？是否有适配公告渠道。

**6. 私有传感器的第三方可调用性**
设备暴露了 `zte.sensor.*`（跌落检测、拿起、电梯检测、活动识别等）私有传感器类型。普通第三方应用能否通过标准 `SensorManager` 调用？若需要签名级权限，是否对外开放申请？

如果上述能力均无开放计划，也请明确告知，我方将仅依赖 Android 标准 API 实现，不再尝试接入。

感谢。
