### S1-1 删除 E2E 密钥文件

**事实**：`zhuli/lastchat/app/src/androidTest/assets/zhuli_e2e_key.txt`（49B，`sk_tr_` 开头）由本地提交 `1e14502` 加入；远端 `7fd13f9`（对应提交）**没有**加入它，远端树 404。所以暴露面是**本地仓库**，不是公开历史。用户已作废该 key。

**步骤**
```bash
git rm --cached zhuli/lastchat/app/src/androidTest/assets/zhuli_e2e_key.txt
rm zhuli/lastchat/app/src/androidTest/assets/zhuli_e2e_key.txt
```

**DoD**：`git ls-files | grep e2e_key` 为空；`find . -name "*_key.txt"` 无结果。
**回滚**：从 `1e14502` 取回（`git show 1e14502:<path> > <path>`），但**不建议**（key 已作废）。

### S1-3 构建期密钥扫描（新增）

**为什么**：`.gitignore` 只能拦"没被跟踪的新文件"。已经 `git add` 过的、或将来有人 `git add -f`，拦不住。要在构建时卡一次。

**位置**：`app/build.gradle.kts` 现有 `tasks.matching { it.name == "preBuild" }` 块内，紧跟 `*.db` 断言之后加：

- 扫描目录：`src/main/assets`、`src/androidTest/assets`、`src/main/res/raw`
- 命中规则：文件名匹配 `*_key.txt` / `*secret*` / `*apikey*`，或内容匹配 `sk-[A-Za-z0-9_-]{20,}`
- 命中即 `throw GradleException(...)`，错误信息给出"请放到 ~/.zhuli/ 并改用 -e 参数"

**DoD**：临时造 `src/androidTest/assets/fake_key.txt` 内容 `sk-abcdefghijklmnopqrstuvwx` → `assembleDebug` 失败且信息可读；删除后恢复成功。
**风险**：误伤（例如文档里出现 `sk-` 示例）→ 只扫 assets/raw，不扫 `.kt`/`.md`。

---

### S1-4 E2E 测试缺 key 时跳过

**现状**：`ZhuliE2ETest.key` 先从 instrumentation 参数 `zhuli.e2e.key` 取，取不到再读 asset，最后 `.getOrDefault("")`。删掉 asset 后 key 恒为空 → 测试会**失败**而不是跳过。

**改法**：在 `@Before` 或每个用例首行加
```kotlin
org.junit.Assume.assumeTrue("未提供 zhuli.e2e.key，跳过联网 E2E", key.isNotBlank())
```
**DoD**：不传参跑 `connectedDevDebugAndroidTest` 时该测试显示 **skipped**；传 `-e zhuli.e2e.key <key>` 时正常执行。

### S3-2 补依赖与源集

现状 `app/build.gradle.kts` 已有 `testImplementation(libs.junit)`（第 427 行），19 个测试只用 `org.junit.*`，**不需要新增依赖**。
唯一可能要动的是 `testOptions`：若出现 `Method ... not mocked`，再加

但先不加——加了会掩盖真实问题。

**DoD**：`:app:testDevDebugUnitTest` 能编译并启动，不是一上来就 `No tests found`。

### S3-3 编译分流

把失败分成三类，**不许混**：

| 类别 | 判据 | 处置 |
|---|---|---|
| A 可编译 | 0 error | 进 S3-4 |
| B 需改 | 符号/签名漂移，语义未变 | 就地改测试，**不改产品代码** |
| C 该删 | 目标类已不存在（Video*） | 删除并在报告里写"随功能一起下线" |

**硬约束**：这一步**不允许为了让测试变绿去改 `core/` 产品代码**。如果测试暴露的是真 bug，单独开一条提交，并在报告里标注"测试发现的产品缺陷"。

### S3-5 门禁结论

判定标准（G1 前半段）：
- 自研 JVM 测试文件 ≥17（19 减 2 个已下线）
- 通过率 ≥90%，剩余失败**全部有归因**
- 无"为了让测试过而改产品代码"的提交

结论只有两种：**可进 M1** / **不可进，缺什么**。
