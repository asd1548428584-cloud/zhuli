### 8 个失败，分三类

| 类 | 用例 | 断言原文 | 性质 |
|---|---|---|---|
| **A. 把真机前提写成了硬断言**（6 条） | `ZhuliB8P0Test.shizuku_installed_check` | "用户设备应已安装 Shizuku" | 模拟器没装 Shizuku → 应 `Assume` 跳过 |
| | `ZhuliSmsIntakeTest.smsPermission_isGranted_andScanRuns` | "真机应已授予 READ_SMS" | 雷电无 telephony → 应跳过 |
| | `ZhuliLocalModelInstallTest.verify_existingRecord_orFile` | "模型文件或记录应至少有一个就位" | 模型未安装 → 应跳过 |
| | `ZhuliLocalE2ETest.localModel_callsZhuliTool...` | `model_not_installed` 异常 | 同上，异常未转成跳过 |
| | `ZhuliB8P0Test.persona_ensure_createsZhuliAssistant_withPrompt` | "应有 zhuli 人格预设" | 新装未走引导，属前置状态 |
| **B. 测试依赖已被删除的资源**（1 条） | `ZhuliCourierInstrumentedTest.queryCourier_fromAssetsSnapshot...` | "真机应查出快递记录，实际 0 条" | 它读的 `zhuli_inbox_snapshot.db` 已在 `1e14502` 因隐私事故删除 → **测试与产品变更脱节** |
| **C. 提醒通知没弹出来**（2 条） | `ZhuliReminderInstrumentedTest.scheduleFutureReminder_firesNotification` | "到点应收到系统通知（150s 内）" | 待判定：雷电通知服务 or 真 bug |
| | `ZhuliReminderBackupTest.reminderNotification_hasThreeActions` | "到点应弹出提醒通知" | 同上 |

**判读**：
- A 类不是缺陷，是**测试设计问题**——把"真机才有"的前提写成 `assertTrue`，导致这套测试在模拟器上结构性变红，等于没有回归价值。正确写法是 `Assume.assumeTrue(前提)`：真机照常验，模拟器明确跳过。
- B 类是**真·漂移**：隐私清理删掉了快照，测试还指着它。
- C 类**需要证据才能定性**。怀疑与雷电的通知投递有关（连 `cmd notification post` 都不进 `dumpsys` 队列），但不能据此下结论。
