## 0. 项目目标（一句话）

在本人手机上运行一个随身 AI 助理：**收到的**（文字/语音/图片/视频）与**冒出来的**（App 通知）信息，全部吃进来 → 结构化存入本地记忆库 → 到点或按事件自动提醒我。做不成全能，就先做成「记得住、叫得醒、不泄露」的三好助理——分享给我的链接能读、物流能查、账记得清，闲来还能陪你聊几句，人格随你捏。

## 2. 功能范围

### 2.1 MUST（第一版必须有）

1. **输入层 M2**：文字消息接收（分享菜单 + 通知文本）并入库
2. **记忆库 M5**：SQLite 结构本地库，记录类型/人名/时间/金额/来源 App/内容摘要；全文检索
3. **提取流水线**：新消息 → 自动分类 → 抽取「待办、时间、人名」
4. **提醒引擎 M6**：从文本中挖掘到期时间 → 生成系统级提醒（闹钟/通知）；含明确日期的直接建，无明确日期的问题化提醒（明早问一句？）
5. **链接阅读**：分享/收到的链接 → 读取正文 → 摘要与关键点进记忆库（详 §2.4-①）
6. **记账**：消息与通知里的收支 + 支付截图 → 自动结构化入账 → 分类统计与周/月总结（详 §2.4-②）
7. **快递查询**：运单号或物流链接 → 查实时状态 → 到件/异常主动提醒（电商收件场景为主，详 §2.4-③）
8. **交互层 M7**：对话式 UI（输入任意信息问「昨天 XX 说啥了」）；主动推送通知
9. **闲聊陪伴（M8）**：不止工具，还能陪你唠嗑——日常吐槽、接梗、跨会话延续话题（详 §2.5）
10. **人格设置（M8）**：自定义名称 / 语气 / 人设描述，多套人格随时切换（详 §2.5）
    - ＋第四轮增补（见 §2.6）：备份恢复、数据库加密、动作边界（只收不发）等为必做项；勿扰分级、快速捕获、晨间简报等为推荐项；其余随手带做

### 2.2 SHOULD（逐步补齐，非首发硬性要求）

- 语音消息 → ASR 转写后进同一条流水线
- 图片 → OCR + 云端图像理解（敏感图走本地 OCR-only）
- 剪贴板监听补漏（复制即收）
- 地理型提醒（到公司提醒交材料类）

### 2.3 WON'T（明确不做）

- ❌ 无障碍服务偷读微信等聊天记录（选择通知+分享路线的直接推论，稳定省电）
- ❌ 所有 App 全自动抓取（做不到也不安全）
- ❌ 视频实时理解（成本/算力不现实，只做抽帧+音轨转写）
- ❌ 取代主力 App 的通知中心（只做助理视角归档）

### 2.4 第二轮增补：链接阅读 · 快递查询 · 记账

#### ① 链接阅读（Link Reading）

- **场景**：把文章、教程、商品页、物流链接丢给助理，助理要知道里面讲了什么，不只是存一个网址
- **技术路线（已澄清）**：用户确认以链接形式分享的都是非隐私内容 → **默认云端摘要 API**（URL + 必要请求头发给云端，返回摘要与关键点入库）
  - 保留兜底：命中敏感特征（订单号、token、登录态参数）的链接 → 只存不抓；云雾失败时才降级到本地 WebView 或「只存链接+标题」
- **隐私规则**：URL 本身可能携带敏感信息（订单号、token）→ 兜底检测命中即「只存不抓」（默认走云端，用户已确认风险可接受）
- **协同**：菜鸟/京东物流类分享链接会被自动识别并转入快递模块（③）

#### ② 记账（Bookkeeping）

- **场景**：「午饭 32」「咖啡 28」「工资到账 8000」→ 自动入账；周/月出分类小结
- **技术路线**：
  - 文字通道：消息/通知 → 本地小模型抽取「金额 / 收或支 / 类别 / 备注」→ 记入与 M5 同一个 SQLite 库的记账表
  - 截图通道（依赖第 6 步图片链路）：支付账单截图 → 本地 OCR 抽「金额 / 商户 / 时间」→ 同表入账
  - 首发固定分类：餐饮 / 交通 / 购物 / 日用 / 人情 / 通讯 / 医疗 / 数码 / 收入 / 其他，后续可调
  - 可选增强：微信/支付宝月度账单 CSV 批量导入（第 6 步再定，现在只记着）
- **隐私规则**：金额按 D2 视为敏感，**全流程本地**，统计不出手机

#### ③ 快递查询（Express Tracking）

- **场景**：丢个运单号说「查一下」→ 返回当前状态 / 下一步 / 预计时间；到件、派送、异常时主动提醒
- **技术路线（第 1 步调研定案）**：
  - 主选：聚合类查询 API（如快递 100 之类），一次接入覆盖多家承运商；个人使用需自己注册拿 Key，第 1 步核实免费额度、覆盖面与条款。用户场景以网购收件为主，承运商全覆盖都要支持
  - 备选：单家官方 API 更稳但接入成本高，个人场景不划算；无 API 时降级为「运单号手动触发 + 复用 ① 的抓取能力」
- **隐私规则**：查询动作本身必须出网（API 感知，不可避免）；运单里的收发地址本地存储时脱敏

### 2.5 第三轮增补：聊天陪伴与人格配置（M8）

#### 闲聊能力
- **长期聊天**：跨会话记得你们的旧梗、你说过的事；聊天记录存进记忆库同一 SQLite 的独立分区，默认持久保留
- **触发提醒（已拍板=自动）**：聊天中提到的日程/约定同样进提醒流水线（与 M6 共用通道），无需另发正式消息；保留配置开关，以后想改成手动随时关
- **引擎分工**：日常闲聊本地模型兜底；重话题或长对话可临时上云 API，聊天内容默认视为含敏感倾向、不命中敏感特征才可上云，否则本地兜底

#### 人格设置
- **可配置项**：名称、口头禅、语气风格、开场白、对用户的称呼
- **多套人格档**：首页一键切换。首发默认一套**通用均衡人格**（已拍板）；之后可自由捏风格（傲娇型 / 温柔型 / 自拟描述，「大肥鱼」这类可作为日后自拟素材）
- **实现方式（定稿原则）**：人格做成**纯数据驱动配置**——改名字/语气/人设描述只动配置不动代码，任意风格随时加档
- **人格≠开关刀**：人格只改变语气与互动方式，**不覆盖**以下安全底线——
  1. 任务必须准确完成（人设不影响答案质量）
  2. 隐私分级 D2 最高优先级不变
  3. 不接受会导致隐私外泄或越权操作的人设指令

### 2.6 第四轮增补：补齐「没想到」的窟窿（全部采纳）

#### A. 存亡类（必做）
- **A1 备份与恢复**：本地加密备份包，支持手动 + 每周自动；一键恢复。**不做云/WebDAV**（已拍板本地方案）
- **A2 数据库落库加密 + App 锁**：整库加密，打开 App 需 PIN / 生物识别
- **A3 动作边界（最高优先级）**：助理**只收不发**——不自动给别人回消息、不转账、不点付款；所有高危操作一律弹人工确认
- **A4 剪贴板雷区**：剪贴板监听先过敏感特征过滤（密码 / 卡号 / token 类），命中即丢弃，不入库

#### B. 省心可靠类（必做）
- **B1 勿扰时段 + 通知分级**：快递到件 = 高优先级；闲聊 = 低优先级；夜间勿扰不尖叫
- **B2 误操作撤回**：自动建的提醒数秒内可撤；账目可改可删，带回收站
- **B3 断网积压补跑**：离线期间的通知进待处理队列，恢复联网自动补齐并去重
- **B4 OEM 后台白名单**：努比亚 MyOS 的自启动 + 电池白名单配置列入第 12 步真机硬验收（不配等于助理睡死）

#### C. 更顺手类（推荐）
- **C1 快速捕获入口**：桌面小组件「记一下…」+ 长按图标快捷指令（记一笔 / 查快递 / 建提醒）
- **C2 重复事项**：周例会、月租、还款日等周期型提醒（第 5 步流水线扩展）
- **C3 晨间简报 + 周报**：每天早上「今日日程 + 重要未读 + 昨日花费」一条推送；周末一份小结
- **C4 日历写回**：**默认双写**（助理记忆库 + 系统日历，可关）——已拍板「直接写系统日历」，与其它日历 App 互通

#### D. 数据治理类（随手带做，绑定早期步骤）
- **D1 每 App 通知开关 + 群聊「仅摘要」模式**（防微信轰炸，第 2 步起生效）
- **D2 实体归一**：「老王」=「王建国」同一人（第 4 步起生效）
- **D3 媒体存储策略**：图片留缩略图+文字摘要、视频只留元数据，防 512G 被吃满（第 6 / 11 步起生效）
- **D4 数据可携带**：JSON / CSV 一键导出，换机不求人

## 3. 隐私与数据规则（D2 的落地细则）

1. **敏感分级默认规则**（第 1 步起做成独立可配置模块，不硬编码）：
   - 命中「人名 / 电话号码 / 证件号 / 金额 / 完整地址 / 公司名+岗位组合」→ 全程本地处理
   - 不含上述字段的普通内容（总结、改写、翻译、提词）→ 可上云 API
   - 拿不准的 → 默认按敏感处理（宁可慢，不可泄）
2. **API Key 由用户自填**，只存 App 私有目录，不入代码库、不入日志
3. **默认值留档**：所有走云的调用留一份本地脱敏摘要（去了人名电话的版本），供复查
4. 模型部署：本地小模型常驻内存过大 → **按需加载、空闲卸载**
5. **聊天与人格配置**：聊天历史及对话中的敏感内容只存本地、不做云同步；人格描述字段本身非敏感（如启用云端闲聊增强可上云）
6. **剪贴板监听安全**：剪贴板内容先过敏感特征过滤（密码 / 卡号 / token 类），命中即丢弃，不入库（§2.6-A4）
7. **本地安全**：数据库整库加密，打开 App 需 PIN / 生物识别（§2.6-A2）；备份包同样加密（§2.6-A1）
