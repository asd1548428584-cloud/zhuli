## 2. 逐个拆解

### 2.1 DSH-Go —— 确认机制与插件形态的教科书

**它是什么**：DeepSeek Harness 的第三方手机客户端。AGPL-3.0（`sdk/` 与 `examples/` 保持 MIT）。

**功能清单**
- 本机运行：App 内装 Ubuntu + Node.js + DSH 引擎，无需 Root/Termux；Flutter 通过本机 HTTP 桥接引擎
- 远程连接：SSH 或 DSHarness Remote，手机变控制器
- 聊天：多模型切换、图片、语音输入（离线听写）、工具审批卡、提问卡
- **可中断生成**：排队 / 立即发送 / 插入当前轮，三种
- **插件界面**：原生工具卡、表单、面板（不是把终端文本塞进聊天）
- 分享：单条生成分享卡、整段对话生成**端到端加密回放链接**（密钥只在链接里）
- 手机操控：读屏、点按、输入
- 外观：主题、图标、桌宠、横屏/平板排版

**关键方法（值得抄）**
1. **三档确认**：允许一次 / 本轮允许 / 取消；确认卡 30 秒自动拒绝。
2. **默认禁止名单**：支付、银行、券商永不触碰；微信每步确认；系统设置、密码/验证码、App 自身默认拒绝。
3. **硬性中止**：3 分钟无操作自动结束；息屏即停；关掉手机操控立即中止在途操作。
4. **诚实标注边界**：README 明写"本机模式 ≠ 本地离线大模型，模型推理仍走你配置的 API"。
5. 插件 SDK 把工具结果做成原生卡片（表格/按钮/表单），而不是让模型吐 markdown。

**短板**：单作者；远程模式功能缩水；插件 SDK 未发布到 npm；内置 Linux 环境吃 1GB 存储。

**可抄**：确认分档 + 禁止名单 + 诚实标注"模型在哪跑"。

### 2.2 NIDO —— 与 zhuli 最像，而且把难题都解了（MIT）

**它是什么**：100% 离线的 Android 个人助理。Expo/React Native + 原生模块，推理走 llama.cpp（`llama.rn`），**MIT 许可**。README 自标 alpha、未经独立审计。

**功能清单**
| 类别 | 内容 |
|---|---|
| 对话 | 本地小模型（Qwen/Phi/Gemma/LFM，0.4–5GB，按内存与语言自动选） |
| 记忆 | 事实、笔记、提醒；生日年度提醒；可选每日 8:00 摘要（默认关）；三语交叉查询；"忘记我的最爱颜色"需确认后删 |
| 动作 | 一次性/周期提醒、倒计时、笔记、日历事件、单位换算、算术、打开链接 |
| 文档问答 | txt/md/csv/json/pdf + 图片/扫描件 OCR，全端上索引 |
| 离线知识库 | 内置 + 可选 Wikipedia 包（约 5 万篇）+ 9 个指南包；**Ed25519 签名知识包**，验签失败即拒 |
| P2P | 蓝牙直连，QR 配对，核对指纹后验证；X25519 + Ed25519 + XSalsa20-Poly1305，默认 **Double Ratchet** + **ML-KEM-768** |
| 应急 | 69 国应急号码、CPR/止血/窒息/烧伤速查 |

**关键方法（这是全文最值钱的部分）**
1. **外部内容永不当指令**：来自联系人、文件、笔记的内容"始终被当作数据，而非指令"；基于它们的写入/发送一律要确认。→ 这是标准的 prompt-injection 防御，**我们目前没有**。
2. **多请求拆按钮**：一条消息含多个请求时，显示成按钮等用户点，不自动全执行。
3. **接地判定（grounding judge）**：答案要标出"哪些句子来自来源、哪些是模型凭空生成"；无匹配就不显示来源。他们用 943 条对抗样本迭代，失败从 285 → 108 → **4**。
4. **按原文回答路径**：知识库覆盖的问题**逐字返回，不加载模型**。省电、可信、低配机也能用。
5. **模型内存管理**：启动只加载"搜索模型"，聊天模型首次发送才加载、**闲置 3 分钟卸载**；低电/省电/发热时降线程；系统报内存压力主动卸载。
6. **兼容性徽章按真实加载计划算**，不按参数表；"过重"的模型干脆不给下载按钮。
7. **密钥不可读就拒绝开库**（fail-closed），**紧急擦除优先销毁数据库密钥**而不是擦文件。
8. **防截屏 + Android 12+ 隐藏其他应用浮层**。
9. 6000+ 自动化测试；P2P 握手做了形式化验证。

**短板**：alpha；蓝牙兼容性看机型；首启要下 0.4–1.1GB 模型；无中文（西/英/葡）。

**可抄**：1、2、3、4、5、6、7 全部。**这是我们最该逐条对照的产品。**

### 2.3 Recall —— "不用大模型也能叫助理"，以及备份的正确答案

**它是什么**：Android 12+ 本地私人记忆库。**Echo 助理是"本地语义规则 + 分类引擎"，不是 LLM**。

**功能**：笔记 / 密码 / 物品位置（房间+货架+拍照）/ 票据 / 提醒 / 支出分析；生物识别；**防截屏与最近任务预览**；悬浮便签气泡；离线 OCR（自动识别电话/日期/邮箱/地址）；**通话式强提醒**（锁屏上像来电一样响 + TTS 播报）；保修与订阅到期；**临时投递**（24 小时自动销毁）。

**关键方法**
- 16 位恢复口令 + 分块 AES-256-GCM → 上传网盘，宣称零知识；**证明"口令丢了就没了"用户能接受，前提是 UI 说清楚**
- 应用内更新带 **SHA-256 校验**
- 权限按场景申请（拍照时才要相机），而不是启动时一锅端

**短板**：没有真语义检索（规则引擎）；备份走 Google Drive（不是纯本地）。

**可抄**：通话式强提醒、临时投递、口令备份 UX、场景化权限申请、SHA-256 校验更新。

---

### 2.4 LastChat / RikkaHub —— 聊天壳 + 设备控制，已经拼好了

**LastChat**：RikkaHub 分支，自述"大幅改过 UI 与**记忆系统**"。
- **本地 RAG 记忆（向量嵌入）**、多模态输入、多 Provider
- **本地设备控制：发送通知、启动应用、读取通知、设置闹钟/提醒**
- 内置 **QuickJS** 执行 JavaScript；联网搜索；多助手/标签；TTS；**WebDAV 备份**
- 栈：Kotlin/Compose/Koin/Room/DataStore/WorkManager/AlarmManager

**意义**：它已经把"聊天壳 + 读通知 + 设闹钟 + 本地向量记忆"拼在一起了。**G1 直接 fork 它，比 fork 裸 RikkaHub 少走约两周**（⚠ 需核实代码质量，README 自述由 Claude/Gemini 生成修改）。

**RikkaHub 本体**：AGPL-3.0，9k 星，MCP、类 ChatGPT 记忆、多模块。适合当"上游"，不适合直接改。

### 2.5 Roubao 肉包 —— 双层 Skills/Tools 与"深链优先"

**它是什么**：安卓版 V1.4.2（**MIT**，已停更）；iOS 2.0（AGPL-3.0，仍在开发）。安卓靠 **Shizuku** 拿 shell 权限，VLM 看屏幕。

**关键方法**
1. **Skills 层（意图层）+ Tools 层（原子层）**：高置信意图走 **DeepLink 委派**（点外卖→美团 scheme；查快递→菜鸟 scheme），跳不过去才走截图循环。
2. **四角色**：Manager 规划 / Executor 执行 / Reflector 反思上一步是否生效 / Notetaker 记笔记。
3. **敏感页面检测**：识别到支付、密码页自动停。
4. **智能定位降级**：本地 OCR 辅助定位，两次失败才让主模型多模态重定位（iOS 版）。
5. 悬浮窗实时展示步骤，可随时停；API Key AES-256 存储。

**短板**：安卓停更；Shizuku 每次重启要重新授权；全自动循环与"只做单步"冲突。

**可抄**：Skills/Tools 分层、**DeepLink 优先**、Reflector（我们缺"执行后校验"这一环）。

---

### 2.6 befikr —— 提醒语义的细节王

**功能**：自然语言快速添加（"call mom fri 5pm"、"water plants every 3 days"）；精确闹钟；**划掉后一小时回来**；**静态周期 vs 自适应周期**；**跳过单次**；通知内完成/稍后/跳过；晨间摘要可选时间或关；桌面小组件；QR 配对 P2P 同步；每日备份保留 7 份；连续打卡与花园。

**方法**：Rust 核心 + JNI，Android/Windows/Linux 共用一套解析与调度；解析结果在输入时高亮，可点掉误识别。

**可抄**：误划恢复、自适应周期、跳过单次、输入时高亮纠错。**这四条直接补我们的提醒短板。**

### 2.7 工具型：AI Edge Gallery / PocketPal / ChatterUI

- **AI Edge Gallery**（Apache-2.0）：Gemma 4、Ask Image、Audio Scribe、**Agent Skills（函数调用）**、内置 TTFT/解码基准。→ 端侧工具声明的官方范本。
- **PocketPal**（MIT）：模型下载/切换/基准 UI 最顺，适合抄"模型管理"。
- **ChatterUI**（AGPL-3.0，2026-04 后停更）：角色卡与采样参数，仅参考。

### 2.8 能力型：Mobile-Agent / ARTEMIS

- **Mobile-Agent**（阿里，8.9k）：ADB + VLM，每步截图复核、自我修正。
- **ARTEMIS**（Google）：**无障碍树 → OCR → 视觉模型** 三级降级，Planner/Operator/**Safety Net**/Checker，AndroidWorld 99%+。
- 共同点：都靠"看屏幕 → 决策 → 注入触摸"，而注入的触摸只有 DOWN/UP、`pressure` 恒 1.0、无 MOVE —— **任何 App 都能识别**。所以"模拟人"是伪命题，我们不做全自动是对的。

## 3. 六个共同问题，他们各自怎么解

| 问题 | DSH-Go | NIDO | Recall | LastChat | 肉包 | befikr | **zhuli 现状** |
|---|---|---|---|---|---|---|---|
| 模型放哪 | 引擎本地/模型云 | 全本地 | 不用 LLM | 可选 | 云 VLM | 不用 | 云 + 三个模型已下载无运行时 |
| 记忆结构 | 会话 | 事实/笔记/提醒 + RAG | 分类条目 | 向量 RAG | Notetaker | 任务历史 | inbox + 账本 + 哈希向量 |
| 提醒可靠 | 无 | 6 类周期 + 摘要 | 精确闹钟 + 强提醒 | 只设闹钟 | 无 | 误划恢复 + 自适应 | 强（引擎已验证），缺误划恢复 |
| 权限确认 | **三档 + 黑名单** | 副作用即确认 + 外部内容当数据 | 无外部动作 | 无 | 敏感页自动停 | 无 | 每步确认，缺分档 |
| 防幻觉 | 无 | **接地判定 + 逐字返回** | 规则引擎 | 无 | Reflector | 无 | 有"没有找到"，无 grounding |
| 备份加密 | 分享链接 E2E | SQLCipher + 擦除 | **口令 E2E** | WebDAV | — | 本地 7 份 | Keystore（跨设备断链） |

**一眼能看出的差距**：权限确认的**可用性**（我们是"每步都烦"）、防幻觉的**可验证性**（我们只有"允许说不知道"）、备份的**可迁移性**（我们卡在 Keystore）。

## 4. 它们都没做的事 = zhuli 的机会

1. **没人做通知采集闭环**。NIDO/Recall 靠用户手动输入；LastChat 能"读通知"但没有分类、去重、来源静音、快递语义。**"信息自己找上门"这件事只有我们在做。**
2. **没人做误报治理**。没有一家有"噪声闸门 + 误报率基线 + 同刻同标题不重建"。这是真机喂出来的。
3. **没人做可解释**。没有"凭什么提醒你"的依据字符串，也没有一屏自检面板。
4. **没人做中文时间/快递/取件码**。NIDO 只有西/英/葡；其他家连中文分词都没有。
5. **没人把"确认"做成既安全又不烦**。DSH-Go 最接近，但它没有"只读汇总"这个中间态（我们的大部分动作其实只需读，不需执行）。

**结论**：不要在"聊天壳"和"全自动操作"上和他们拼，那两条已经卷死。把"通知→结构化→提醒→可解释"这条链做深，同时把他们验证过的零件（确认分档、grounding、内存管理、口令备份）搬过来。

## 5. 对 zhuli 的 10 条产品级结论

| # | 结论 | 来源 | 落地动作 |
|---|---|---|---|
| 1 | **"本机运行"和"本地模型"必须在 UI 上分开说** | DSH-Go 的诚实标注 | 自检面板加一行"模型在哪跑/数据去哪" |
| 2 | 确认要分**三档 + 默认禁止名单** | DSH-Go | 已在 V3.1 §1.3 写入 |
| 3 | **外部内容永远当数据，不当指令** | NIDO | 新增 T-B10：通知/链接/文件文本进入 prompt 前加隔离与指令声明 |
| 4 | 答案要能区分**引用与生成** | NIDO grounding judge | 新增 T-C6：回答附来源句，无来源句标"推断" |
| 5 | 知识库覆盖的问题**直接逐字答**，不加载模型 | NIDO | 提醒依据、快递、账本类问答走模板，不进 LLM |
| 6 | 模型要**按需加载、闲置卸载** | NIDO | T-H3 验收加"闲置 3 分钟卸载、内存压力主动卸" |
| 7 | 提醒要有**误划恢复 + 自适应周期 + 跳过单次** | befikr | 新增 T-D9 |
| 8 | 强提醒可以**像来电一样响 + TTS** | Recall | 高置信提醒的可选形态（设置里开） |
| 9 | 备份用**口令派生**，并明确"丢了就没了" | Recall / NIDO | T-E6 已有，补 UI 文案 |
| 10 | Skills 与 Tools 分两层，**深链优先** | 肉包 | T-H5/T-H6 已改 |

**另外三条明确不做**（调研后更确定）：
- 不做内置 Linux/PRoot（1GB、耗电、我们不需要跑代码）
- 不做 Shizuku/ADB 自动化（重启失效、权限面大）
- 不做全自动 GUI 循环（触摸特征可识别、误操作代价高）

## 7. 仍需核实
