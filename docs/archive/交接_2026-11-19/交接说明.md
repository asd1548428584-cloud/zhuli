### 3.8 第 8 步（语音链路，🔄 本体完成 / 转写待云 Key 验证）

**新增**：`VoiceNote.kt`；`ShareReceiverActivity` 加 `audio/*` 分支；`InboxDatabase.applyVoice()`；

**已真机验证**：语音进分享目标（秒回执）→ 音频复制进私有目录 + 时长解析（3s 读出 3s）→
本地识别尝试（默认 + 逐个注册服务 + 显式 ComponentName）→ 失败诚实落库
`[语音（3s）] 未转写：<原因>` 且保留音频待重试。

**本机硬结论**：`pm query-services -a android.speech.RecognitionService` 只有 1 个第三方服务
（`dev.davidv.translator`），默认与显式点名**都 `ERROR_CLIENT`**；Google 语音未注册该接口，
ZTE/高通那几个包是唤醒词服务。→ **这台 ROM 没有第三方可用的语音识别服务**。

**未验证（需要你出手）**：云端兜底走 OpenAI 兼容 `/audio/transcriptions`（multipart，`whisper-1`），
代码已实现但无 Key。要在云设置里填 BaseURL + Key 并勾「允许语音上云」才能验证；
隐私口径：语音默认不出机，必须显式同意。

```
reminders 308 条：07:30、08:00、09:00 三个整点各 100 条同时 fired（fired_at 同秒）
标题一路累加：「闹钟(预定的闹钟) 周五07:30 - 传软件 07:30 07:30 07:30 …」
```

**根因是一条闭环**：

```
系统闹钟/日历通知 → 监听器收下 → 提取 deadline → 建提醒
  → 建提醒时双写系统日历（提前 10 分钟提醒）→ 日历 App 弹通知
  → 又被自己的监听器收下（日历包当时不在过滤名单）→ 再建提醒 → 再写日历 → …
```

每 10 秒放大一轮，最后一分钟堆 100 条同刻提醒，100 个闹钟同秒到点 → 100 条通知。

**四道修复**（`core/` 6 个文件，库升 v7）：

| 层 | 做法 |
|---|---|
| 入口 | `NoiseGuard` 回声源黑名单（日历/时钟/健康/商店/系统 android，包名+关键词双匹配） |
| 入口 | 10 分钟同文去重 + 标题前缀去重（治"通知被反复更新越滚越长"）+ 同包 10 分钟 20 条熔断（聊天类豁免） |
| 建提醒 | 回声/噪声源不建（含「预定的闹钟」文案）、同刻同标题不重排、单轮最多 15 条 |
| 出通知 | 到点只标 fired，1.2 秒合并窗口统一 flush；>3 条只发一条汇总；通知归组 |

**自愈**：`NoiseGuard.purgeOnce()` 装好新版首次启动时跑一次，删回声/噪声源的行、它们的提醒、
以及已经写进系统日历的事件，并合并同刻同标题重复提醒。

**真机验证（NX733J）**：收件 1002→148、提醒 308→8（7 条重复合并成 1）；
日历 App 09:37:50 真弹了通知而本 App 收件 0 条；同文连发 25 次只入 1 条；25 条不同通知压测精确停在 20 条；
单条提醒 due 10:11:24 → fired 10:11:24 弹 1 条独立通知；6 条同刻提醒最终只剩 1 条「⏰ 6 条提醒到点了」汇总。
事故期间写进系统日历的 **182 条重复日程也一并清掉**（只留 2 条在用的）。

**两个实现坑（都已修，别再踩）**：
1. `ADD COLUMN notified INTEGER NOT NULL DEFAULT 1` 会把之后新建的提醒也标成「已弹过」→ 全都静默不弹。
   正确姿势：列默认 0，迁移时 UPDATE 老行为 1。
2. 这台 ROM 的 `setAlarmClock` 是排队递送的（5 个同刻闹钟回调落在 0/1.2/2.5/3.7/4.9 秒），
   1.2 秒合并窗口只抓得到一条 → 追加「一分钟内已响超过 3 条就撤掉单条、折叠成汇总」。

**装机坑**：换过签名的 APK 会 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`；`pm uninstall -k` 在这台 ROM 上
留半卸载记录（`pkg=null` 但 codePath 还在），要再 `adb uninstall` 一次才能装（数据会丢，先备份库）。
本次因此清了库，脏数据由自愈逻辑重新验证（把备份库灌回去跑 purgeOnce 复核）。

### 3.10 第 9 步（云 API 兜底 + 敏感路由，✅ 真机验收 · 2026-11-20 上午）

**做了什么**：把散在三处的出网调用（闲聊 / 链接摘要 / 语音转写）收成一个受控出口，并补齐隐私口径。

- `PrivacyRouter`：出网唯一闸门 —— 没配 Key / 地址非 HTTPS / 命中敏感，三条任一不过就留在本地；
  通过则放行并留档。
- `CloudClient`：唯一 HTTP 出口（`/chat/completions` 与 `/audio/transcriptions`），统一超时、错误码、
  UA、留档；**连不上也要留一条失败记录**（第一版漏了，验收时发现）。
- `SecureKeyStore`：Key 用 Android Keystore AES-256-GCM 加密后存 SharedPreferences，
  老明文 Key 首次读取自动迁移并抹掉（`shared_prefs/zhuli_secure.xml` 里只有 `api_key_enc` 密文）。
- 库升 **v8**：`cloud_log(at, task, host, model, request_redacted, ok, note)` —— 只存脱敏摘要。
- 壳加「出网记录」（查我到底发了什么）与「隐私自检」（8 条样例当场判一遍）；云设置拒收非 HTTPS，
  已配置时 Key 输入框留空表示不改。
- `network_security_config.xml`：全局禁明文，只给 `127.0.0.1/localhost` 开口（验收用 `adb reverse`）。

**敏感口径两处修正**（验收当场抓到）：
1. **金额**：原正则要求「数字+元/块」，`¥545.60`、`收入 ¥8000` 这类**带币种符号不带单位**的写法全漏判，
   而记账小结正好是这种形态 → 历史轮次会把账本带出机。改成「有 ¥/￥/$ 就算敏感」。
2. **地址**：原来单字「道/街」就算敏感，连「我知道」都被判成地址，云端等于永远用不上 → 必须成结构才算。

**验收（NX733J，假端点 + adb reverse）**：
| 用例 | 结果 |
|---|---|
| 非敏感闲聊 | ✅ 上云，假服务收到请求 |
| 手机号 / 金额 / 地址 / 公司+岗位 / 证件 / 验证码 | ✅ **0 请求**，回复说明「按规矩只在本地说」 |
| 历史轮次带敏感内容 | ✅ 请求体替换成 `[已省略：含敏感内容]`，全文搜不到号码与 `¥` |
| 云端不通 | ✅ 本地兜底 + 失败留档 |
| Key 落盘 | ✅ 仅密文；清空后 `zhuli_secure.xml` 变空 map |

**验收环境坑（踩过，记下来）**：
- `am start --es q` 只在**冷启动**生效，Activity 已在栈里时走 `onNewIntent`（老壳没实现 → 第二次起静默丢失，已补）。
- 必须**亮屏解锁**再验：息屏时进程冻结，`am start` 进去了也不执行，看起来像功能坏了
  （截图全黑、18KB 左右＝黑图，不是渲染问题）。
- 这台机器 adb 服务会反复重启，`adb reverse` 映射随之丢失 → 每次测试前重建 reverse，否则一律「连接被拒」。
- 改库仍走「`exec-out run-as cat` 拉出 → Python 改 → base64 分块写回」，手机上没有 sqlite3。

### 3.11 第 10 步（快递识别 · 不查接口版，✅ 真机验收 · 2026-11-20 中午）

**为什么不接 API**（按用户"我不会、有没有别的办法"的追问去摸底）：
- 系统自带快递卡片（中兴「智慧建议」`com.zte.mifavor.suggest`）的数据出口 `SuggestOutProvider`
  受 `suggest.permission.provider.read` 保护，level = **`signature|privileged`**；第三方和 shell 都是 SecurityException。
- 快递100/快递鸟/各家开放平台：要注册、实名、审核、付费或商家资质。
- **但快递信息本来就会发到手机上**：实测 3909 条短信里 751 条是快递短信，格式规整（承运商/驿站/取件码/地址齐全）。

**做法**：三条本地通道（短信 / App 推送 / 分享文本）共用 `Express.parse()` + `CourierIntake.intake()`：
- 解析承运商（【】标签优先）、驿站（`到XX驿站/超市/门市/车库` 优先，其次品牌+店名）、
  取件码（`8-4-2013` / `取件码1234` / `凭XX取货`）、状态（到站/派送/滞留/签收）、运单号（可选）；
- 入库为 `category=快递` 的收件行，`note` 是一行摘要，`deadline` = 到站 +2h（不晚于 20:30）；
- 立刻 `ReminderEngine.scanAsync` → 建「去某驿站取件，码 xxx」提醒；只有 12h 内到站的才排（旧短信只留记录）；
- 去重：同摘要 3 天内只记一次（短信与推送常是同一件事）。

**真机验收**：扫 7 天 → 751 条命中、入库 7 条（其余签收超 24h/重复）；驿站与取件码全对；
分享「刚到站」短信 → 入库 + 提醒 13:13 + 闹钟排上；同一条分享两次只入 1 条；
对话「我的快递到了吗」→ 待取 2 件（带码与提醒时刻）+ 7 条历史。

**坑**：`java.util.regex.Pattern` 没有 `find()/groupValues`（那是 Kotlin Regex），要 `matcher().find()/group(1)`；
驿站名要把「】」和尾部动词切掉；分享/通知通道写完库必须显式触发 scan，否则只入库不排闹钟（分享路径最初就漏了）。

**隐私**：解析全在本机；运单号/取件码不上云、不进 cloud_log；短信只解析命中快递特征的那些，其余不落库。

### 3.13 第 16 步（设置可自定义 + 三个能力论证，2026-11-20 下午）

用户追加要求：①操作 App 能力也加 ②本地模型 NPU/GPU 哪个好 ③设置要可自定义 ④对话里能加功能（**只论证**）。

**已实现（v0.12 / versionCode 12 / 库 v10）**：
- 「设置」面板集中 6 个开关 + 本地模型后端四选一 + 无障碍入口，改完立即生效；
- `DailyBrief.show` 认简报开关；库建 `skills` 表（**只建表，未接线**）。

**结论一：本地模型 NPU vs GPU**（针对 SM8750 + Android 15）
- NPU：INT8 吞吐高、功耗低 3–5 倍，但 QNN 量化/固定 shape 有坑、难调试 → 适合**短输入结构化任务**（分类/抽取/嵌入），2B 以内。
- GPU：算子覆盖最全（MLC-LLM 路线），长文本生成更现实，但发热掉频。
- `auto` 别猜，要**首次运行自测**（同 prompt 三种后端各跑一次，取最快且不掉频的，结果缓存）。

**结论二：操作 App 能力 —— 可做，但只做"单步辅助"**
`AccessibilityService` 读节点树 + `performAction(CLICK)` 即可（Buddy 同路线，因此上不了商店）。
必须抄四个安全机制：每步确认、per-app 白名单（支付/聊天默认禁）、触摸即暂停、每步留痕。
落地顺序：只读「屏幕上有什么」→ 单步点击「点『确定』」→ 多步任务（需模型规划）。
不做批量自动化/代发/代付（违反只收不发红线）。

**结论三：对话里加功能 —— 可行，但限定"参数化技能"**
A 参数化技能（动作固定：提醒/归类/静音/摘要/周期，自然语言只填参数）✅ ；
B 组合流程 ⚠️；C 模型生成代码动态加载 ❌（要沙箱与审计，一个 bug 就能写坏数据）。
最小形态：「以后收到快递短信，半小时后提醒我取」→ 存规则 → 命中执行 → 说「我的规则」可列可删。
**为什么先不接线**：价值在"加得稳"，规则冲突/优先级/误伤三件事的验收口径要先定。接线约 2–3 小时，表结构已就位。

## 4. 关键技术结论（别踩第二遍）

### 4.1 闹钟：必须用 `setAlarmClock`
`setExactAndAllowWhileIdle` 在努比亚 MyOS 息屏后被限流（实测 due 17:26:21，到 17:26:55 仍未响）。
改用 `AlarmManager.setAlarmClock(AlarmClockInfo(trigger, showIntent), pi)` 后**偏差 0 秒**。
代价：状态栏会出现闹钟图标（对提醒类 App 是合理代价）。
仍保留 `setExact → setAndAllowWhileIdle` 降级链，无权限也不崩。

### 4.2 双层兜底
- 精确闹钟：准点。
- 15 分钟心跳（`setInexactRepeating`，不需要额外权限）+ **开 App 立即 sweep**：补漏。
- `ensureAlarmsWith` 里，超过 1 分钟的过期提醒**不再重排**（否则会排成「现在+5秒」，变成连环响）；超过 1 小时的直接标 canceled。

### 4.3 Android 15 边到边
targetSdk 35 下不清 insets，内容会画到状态栏底下（顶部文字被压住）。
解法：`Theme.Material.Light.NoActionBar` + `setOnApplyWindowInsetsListener` 补 padding。

### 4.4 adb 注入中文
`am start ... --es KEY "带空格中文"` 会被 shell 按空格切碎（只送到第一个空格前）。
必须双层引号：`adb shell "am start ... --es android.intent.extra.TEXT '午饭 32 元'"`。

### 4.5 这台机器 logcat 是死的
`adb logcat -d` 返回 0 行（MyOS 限制）。**不要靠日志排查**，改用：
- 数据库直读：`adb exec-out run-as com.zhuli.app cat databases/zhuli_inbox.db > z.db`（无 WAL，journal=DELETE，直接读即可）
- `adb shell dumpsys alarm | grep -A3 com.zhuli.reminder.FIRE`
- `adb shell "content query --uri content://com.android.calendar/events --projection title:dtstart:calendar_id:hasAlarm"`
- 壳里的「提醒检查」面板（同进程读库，最可信）

### 4.6 离线验证 Kotlin 逻辑的土办法
不用折腾独立 kotlinc（会报 IR lowering 内部错误）。直接拿 Gradle 编出来的 class：
```
javac -encoding UTF-8 -cp app/build/tmp/kotlin-classes/debug;kotlin-stdlib.jar;android.jar -d jout Smoke.java
java  -cp jout;...; Smoke
```
脚本在 `D:\zhuli-dev\smoke\Smoke.java`。第 4 步的 4 个时间/金额 bug 就是这么抓出来的。

### 4.7 读上一轮的 dsh 会话（需要的话）
`C:\Users\chaoxi\.dsh\sessions\--C-gzq-zhuli--\session-12c6951f.../session.v4.jsonl.zstd`
是多帧拼接的 zstd：用 node 逐帧解（`zlib.zstdDecompressSync`，按 magic `28 B5 2F FD` 切分），得到 jsonl 后按 `type == user/message|assistant/message` 提取。
